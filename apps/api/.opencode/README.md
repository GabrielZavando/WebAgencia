# .opencode/ — OpenSpec Experimental Skills & Commands

> **Do not edit these files manually.**
> These are official OpenSpec 1.4 templates generated by the OpenSpec CLI.
> When OpenSpec is updated, regenerate with: `openspec update`

## Purpose

This directory contains the **official OpenSpec skills and command templates** for the SSD workflow.
They are referenced from `opencode.json` commands:

| Command in `opencode.json` | Skill file |
|----------------------------|------------|
| `/opsx-explore` | `skills/openspec-explore/SKILL.md` |
| `/opsx-propose` | `skills/openspec-propose/SKILL.md` |
| `/opsx-apply` | `skills/openspec-apply-change/SKILL.md` |
| `/opsx-archive` | `skills/openspec-archive-change/SKILL.md` |

The command files (`.opencode/commands/*.md`) are the same content in a simpler format
and are kept for reference compatibility with older OpenCode versions.

## Difference from `ai-specs/`

| Directory | Contents | Source |
|-----------|----------|--------|
| `ai-specs/` | Agency Zavando custom agents and skills (enrich-us, commit, code-auditing, etc.) | Agency-defined |
| `.opencode/` | OpenSpec official skills for SSD workflow | OpenSpec CLI |

Do **not** mix these. `ai-specs/` is the source of truth for agency-specific workflows.
`.opencode/` is the source of truth for the OpenSpec SSD protocol.

## Regenerating

If OpenSpec releases a new version, update the skills:

```bash
npx openspec update
```

This will refresh all files in this directory to match the latest official templates.

## Dependencies

This directory has its own `package.json` with `@opencode-ai/plugin`. Do not delete it.
The plugin is used by OpenCode to provide OpenSpec-specific tooling.
